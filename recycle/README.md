# Unicel Greens – Battery Recycling (Odoo 18 migration)

Modules: `ug_recycling_base`, `ug_lot_assay`, `ug_recovery_planning`, `ug_epr`, `ug_mass_balance`
(migrated from the Odoo 20 source; requires Odoo 18 Enterprise for `quality_control`).

## Changes made for Odoo 18

**Manifests**
- Version `20.0.1.0.0` -> `18.0.1.0.0`.
- `security/ir.access.csv` -> `security/ir.model.access.csv`, converted to the 18 format
  (`model_id:id`, `group_id:id`, `perm_read/write/create/unlink`).
- Rows with a domain (multi-company) moved out of the CSV into `ir.rule` records in `security/ug_rules.xml`.

**Security**
- Removed `res.groups.privilege`/`privilege_id` (Odoo 19+); groups now use `category_id` on the `Recycling` category.
- Removed `sequence` on groups; `user_ids` -> `users`.
- `group.all_user_ids` -> `res.users` search on `groups_id`.

**Python**
- `models.Constraint(...)` -> `_sql_constraints`.
- `self.env._()` -> `_()`.
- UoM: Odoo 18 has UoM categories, so `_has_common_reference` was replaced by a `category_id` check against the Weight category;
  added `_ug_compare` / `_ug_is_zero` helpers (no `uom.compare/is_zero` in 18).
- Field renames: `mrp.bom/bom.line/byproduct/mrp.production .uom_id` -> `product_uom_id`;
  `stock.move.uom_id` -> `product_uom`; `stock.move.line.uom_id` -> `product_uom_id`;
  `sale.order.line.product_uom_id` -> `product_uom`; `lot_producing_ids` -> `lot_producing_id` (single lot in 18).
- `digits='Product Unit'` -> `'Product Unit of Measure'`.
- `_set_qty_producing(pick_manual_consumption_moves)` override rewritten: Odoo 18 also rescales picked
  moves, so operator-entered weights are saved and restored.
- Main-product lot is no longer generated by Odoo 18 on done: it is created automatically for recycling MOs
  (`<product code>-<MO number>`) together with the by-product lots.
- `_get_moves_finished_values` uses `vals['product_uom']`.
- SQL views (To Process queue, Mass Balance, Material Output): UoM conversion rewritten with `category_id` + `factor`
  (no `parent_path` on uom); stock value taken from `stock_valuation_layer` (no `stock.move.value` in 18).
- Computed chain / next-stage fields got `@api.depends` so they are not stale.

**Views / XML**
- Anchors adapted to 18 views (MO form: `label[@name='bom_label']`; lot form: existing notebook;
  picking form: `move_ids_without_package`).
- Material-symbol icons replaced by Font Awesome (`fa-flask`, `fa-sitemap`, ...).
- Demo BoM data: `uom_id` -> `product_uom_id` on `mrp.bom`, lines and by-products.

**Tests**
- Ported to the same renames; `tracking=False` -> `'none'`, `group_ids` -> `groups_id`, move `name` required.
- Known: some tests not re-verified after the last change (lot-assay "block recover consumption", chain/next-stage).

## Access control (single group)

The whole app is switched on by **one** group: `ug_recycling_base.group_ug_user` ("Recycling Access", category *Recycling*).
Enable it per user under Settings > Users > Access Rights > Recycling. `base.user_root` and `base.user_admin` are in it by default.

- Replaces the former Recycling User / Lab Technician / EPR Officer / Recycling Manager groups; every reference
  (menus, views, `ir.model.access.csv`, Python `has_group` / `_ug_check_group` checks, tests) now points to `group_ug_user`.
- The group implies `mrp.group_mrp_manager`, by-products, routings, lots and quality user.
- Users outside the group see standard Odoo: the Recycling menu is hidden and every field, tab, button, filter and
  list column the modules add to MO, BoM, Product, Lot, Quant, Transfer and the Change Production Qty wizard is not rendered.
  The two settings blocks (EPR basis / product, block unassayed lots) are also group-only.
- How it is done in Odoo 18: `groups_id` is not allowed on inheriting views, so form blocks are wrapped in
  `<t groups="ug_recycling_base.group_ug_user">`, tabs carry `groups=` themselves, and search/list views
  (which reject `<t>`) have `groups=` on each field/filter/button.
- Side effect of merging: there is no separation of duties any more (the same user can submit, approve and reject an assay,
  or create EPR certificates).
- Tests: the role-separation tests in `ug_lot_assay` (lab user cannot approve) and `ug_epr` (user without EPR group refused)
  expect restrictions that no longer exist and will fail; they have not been updated or re-run.
